# nexgraph v0.12 (platform 0.12): improvements found by running an open land registry extract

Dataset: `TN_Land_Registry_1000_Sample_Records1.csv` (1,000 parcel records, 19 columns: record id, district / taluk / village, survey and
sub-division numbers, owner, owner mobile, area in acres, land / soil / usage type, market value in INR, record status, VAO / revenue-inspector /
tahsildar workflow, last-updated date as dd/mm/yyyy). It is kept as `tests/fixtures/tn_land_registry_1000.csv`.

Not tested: the NI Government Land and Property Register in the data.gov.uk link you gave (OpenDataNI, parcels as GeoJSON / shapefile). That host
was not reachable from the build environment. Nothing here handles geometry yet, so that dataset would exercise a different path (a GeoJSON loader).

## What the dataset exposed

| # | Finding in v0.11 | Fix in v0.12 |
|---|---|---|
| 1 | **Same-named places were merged.** The extract reuses `Taluk-A..D` under all 5 districts and `Village-1..20` under every taluk. Member nodes were keyed by the bare cell, so the importer produced **4 Taluk and 20 Village nodes where the data has 20 and 367**. Each merged node joined unrelated districts, and every spectral / community / path procedure then saw links that do not exist | `HyperOpts.qualify`: a member is keyed `parent/parent/value` (`District/Taluk/Village`). Platform: `qualify=Taluk:District,Village:District:Taluk`. Empty parent cell: row skipped and counted. Bad column names are refused before anything is written |
| 2 | Identifier columns became numbers. `Owner Mobile Number` was stored as an integer (summable, and exported to BI as a measure) | `HyperOpts.string_cols` / platform `string_cols=`: kept as text, trimmed |
| 3 | No way to name a column like `Land Area (Acres)` in NQL: `WHERE e.Land Area (Acres) > 3` could not be written, so plain queries on real exports were impossible (procedures took the name as a string and worked) | Backtick-quoted identifiers: ``e.`Land Area (Acres)` ``; a doubled backtick is a literal one. A quoted reserved word still behaves as the word |
| 4 | Importing the file needed a hand-written `members=`, `time=`, `dedup=`, `date_format=`, `qualify=`, `string_cols=` | Preset `land_registry_tn` (label `PARCEL`) |
| 5 | No land / title analytics: every question needed an external pandas script | `land.*` procedures (`src/land.rs`), tenant-callable (the security allow-list needed the `land.` prefix) and five entries in the Analytics catalog (group "Land registry") |
| 6 | The error text for an unknown procedure did not list the new ones | Updated |

## New procedures

| procedure | answers |
|---|---|
| `land.conflicts(label, parcelKeys, ownerKey[, limit[, filter]])` | records sharing a parcel key: `competing_owners` (a title conflict) or `repeated_record`; records missing a key are reported, not dropped |
| `land.rule_check(label, ifCond, thenCond[, groupKey[, filter[, idKey]]])` | records meeting `ifCond` but not `thenCond`, by group, with a Wilson 95 % interval and sample record ids; a record where either condition cannot be evaluated is `unknown`, never a violation |
| `land.hotspots(label, groupKey, outcome[, filter[, minN]])` | rate of an outcome per office or area against the overall rate: z, p-value, Wilson interval, Bonferroni flag |
| `land.valuation(label, valueKey, areaKey[, groupKey[, filter]])` | value per area: weighted, median, quartiles, Tukey fences on `ln(value/area)`, outlier counts; missing and non-positive values are excluded and counted |
| `land.survey_check(label, surveyKey, subKey[, groupKey[, filter[, idKey]]])` | malformed survey numbers, and survey numbers whose `/sub-division` part disagrees with the sub-division column |

A group key may name several columns (`District,Taluk`), joined with `/`. A parcel key must be the **qualified** one: on this extract the bare
`Village,Survey Number` pair reports 5 "competing owners" that are all different districts, and the qualified key reports none.

```
POST /api/import/incidents?preset=land_registry_tn
CALL land.rule_check('PARCEL','Record Status=Active','Tahsildar Approval Status=Approved','District',null,'Land Record ID') YIELD *
CALL land.hotspots('PARCEL','Village Administrative Officer (VAO)','Record Status=Under Dispute',null,10) YIELD *
CALL land.conflicts('PARCEL','District,Taluk,Village,Survey Number,Sub Division','Owner Name') YIELD *
```

## Evidence

* `tests/land.rs`: 16 tests. Small tables with hand-derived numbers (a first draft of five of my expected values was wrong; each was re-derived with
  numpy / scipy before the test was changed, and the engine's figures were right every time), and `real_registry`, which loads the real CSV and
  replays **125 cases** generated by `tests/fixtures/land_expected.py` with pandas, numpy and scipy (Wilson via `scipy.stats.binomtest`, p-values via
  `scipy.stats.norm`, quartiles via `numpy.quantile`). All match to 1e-9 relative. Regenerate:
  `python3 tests/fixtures/land_expected.py tests/fixtures/tn_land_registry_1000.csv tests/fixtures/land_expected.json`.
* `land::tests` (unit): `erfc` against reference values (relative 1e-9 at 1, 3 and 4), and the survey-number parser.
* Platform: `land_registry_through_the_api` (needs PostgreSQL via `NGP_TEST_PG_URL`; the CSV is a fixture): bad `qualify` / `date_format` give 400, the
  preset imports 1,000 / 1,000 rows, node counts are 20 taluks / 367 villages / 5 districts / 1,000 parcels, all five catalog analytics run from their
  defaults, and the same 125 cases match through `/api/query`. Unit tests for argument compilation, including injection attempts in group keys and conditions.
* See the end of this file for the full-suite result.

## Findings about the data (descriptive)

* 1,000 parcels, 5 districts, 20 taluks, 367 villages (about 2.7 parcels each), no repeated records, no malformed survey numbers, no missing cells,
  all dates parse day-first (2024-01-01 to 2025-12-01).
* **No competing owners** on the qualified parcel key (`District, Taluk, Village, Survey Number, Sub Division`): no parcel appears twice.
* **Survey number versus sub-division column: 817 of 1,000 disagree** (183 agree). `Survey Number` carries a `/n` suffix and `Sub Division` is a separate
  column; they are two encodings of one thing and are inconsistent.
* **Status against approval:** of 328 `Active` records, 211 (64.3 %, Wilson 59.0 to 69.3 %) are not `Approved` by the tahsildar (111 rejected, 100 pending).
  Of 332 `Under Dispute` records, 101 (30.4 %) are `Approved`. The nine status-by-approval combinations are almost equally frequent (100 to 123 each), which
  is what independent random columns look like.
* **No dispute hotspots.** Rate of `Under Dispute` is 33.2 % overall. Among 49 VAOs with at least 10 records, 4 are nominally significant at 0.05
  (about 2.5 expected by chance) and none survives the Bonferroni threshold; for 20 district-taluk cells, 0 are; for rejection by revenue inspector (30
  tested), 1 is nominal and none survives. There is no evidence in this extract that any officer or area is unusual.
* **Valuation:** median value per acre 311,896 INR; 11 parcels exceed the upper log-scale fence (3.36 M INR per acre), none fall below the lower
  (30.7 k). Value per acre ranges from 36.6 k to 5.6 M because area (0.5 to 9.99 acres) and value (300 k to 3.0 M) look independent.
* Taken together (uniform columns, `Owner-1..1000`, `Village-n` reused everywhere, 1,000 unique mobile numbers) the extract is **synthetic**. Results
  validate correctness and behaviour on land-registry-shaped data, not real-world title or valuation conclusions.

## Limits

* Qualified keys apply to member columns of a hyperedge import. The shell command `import hyper` splits on whitespace, so it still cannot import
  columns with spaces; use the API or the library. It does not take `qualify` or `string_cols` yet.
* `VAO` and `Revenue Inspector` are not qualified in the preset: in this extract `VAO-23` serves villages in every district, which is not how a real
  VAO works, so there is nothing to qualify them by. In real data qualify them by village or taluk.
* No geometry: parcels are records, not polygons. Boundary overlap (the usual source of real title conflicts) needs a GeoJSON / shapefile loader and a
  spatial index, neither of which exists here.
* `land.hotspots` uses a normal approximation for the z test; for groups near the `minN` of 10 with an extreme overall rate an exact binomial would be
  better. The Bonferroni flag is deliberately conservative.
* `land.survey_check` understands numeric survey numbers with an optional letter and `/digits` suffix (`774`, `12A`, `774/4`). Other conventions (hyphen
  separators, alphanumeric sub-divisions) are reported as malformed.
* `frontend/dist` was not rebuilt; the UI reads the catalog, so the new analytics should appear, but this was not checked in a browser.
* Compiled and tested with rustc 1.97 only (`rust-version = "1.85"` unverified). Code is largely AI-generated; review before production use.
